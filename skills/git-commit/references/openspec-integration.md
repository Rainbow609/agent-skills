# openspec 工作流整合

提交时若侦测到 openspec 活跃变更，且任务已全部完成，应先提示用户归档（`/opsx-archive`）再提交，避免已完成的 change 滞留。

## 侦测时机

提交流程步骤 0 执行一次侦测；openspec 未安装或无活跃变更时，本文件其余内容无需加载。

## 侦测命令

```bash
openspec list --json 2>/dev/null
```

- 命令失败（openspec 未安装或无 `openspec/` 目录）→ 跳过此检查，继续正常提交流程
- 有活跃变更 → 依据下方完成度判定表决定提示策略

## 完成度判定

| 变更状态 | 行动 |
|----------|------|
| `status: "complete"`（所有任务完成） | 提醒归档 |
| `totalTasks > 0` 且完成率 ≥ 80% | 提醒归档 |
| `status: "in-progress"` 且完成率 < 80% | 仅标记为参考信息 |

## 提示模板

```text
【openspec 侦测】侦测到 N 个活跃变更：
  ✓ <name>（M/M 任务完成）→ 建议先归档再提交
  ⚠ <name>（M/N 任务完成）→ 接近完成

是否先执行 /opsx-archive 归档已完成的变更？
  1. 先归档再提交（推荐）
  2. 直接提交（跳过归档）
  3. 稍后手动归档
```

## 边界

- 归档操作由 openspec-archive-change 技能处理，本技能不介入归档流程
- 用户选择"直接提交"或"稍后手动归档"→ 继续正常提交流程，本次会话不再重复提示
