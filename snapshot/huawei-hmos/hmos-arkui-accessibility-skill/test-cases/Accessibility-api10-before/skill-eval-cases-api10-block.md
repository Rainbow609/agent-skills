# ArkUI 无障碍 Skill 评测用例集 · 低 API 版本门禁阻断（API10 工程）

> 工程环境：Accessibility-api10-after，`compatibleSdkVersion = "4.0.0(10)"`（API 10）、`targetSdkVersion = "26.0.0"`。
> 9 个场景页均为未适配原始业务代码——**阻断即终态**，所有用例均不应产出无障碍属性代码。
> 用途：验证 Skill 工作流第 2 步 **API 版本门禁的阻断侧**——本工程全部涉诉属性的最低 API（11/12/13/18）
> 均高于 compatibleSdkVersion=10，Skill 应逐条拦截：说明需 API X+、给出字段提升的具体修改建议、
> **不生成无法编译的代码**。
> 与放行侧互补：`../Accessibility-after/skill-eval-cases-full.md`（API 26，24 页全适配）。
> 输入基准：本工程 `skill-eval-user-inputs.md`（纯净版 9 条，不含任何属性名与预期提示）。

## 通用阻断预期（9 条用例一致）

1. 读工程 `build-profile.json5` 版本字段：`compatibleSdkVersion = 10`（compileSdkVersion 未显式配置，
   以 compatibleSdkVersion 为判定下限）、`targetSdkVersion = 26`；
2. 按 Skill 规则"三字段任一低于属性下限 → 阻断"判定：10 低于全部涉诉属性下限 → **阻断**；
3. 输出包含三要素：① 需 API X+ 的说明（对应属性下限）；② compatibleSdkVersion 提升到目标 API 的
   具体修改建议（版本串格式 "X.Y.Z(N)"）；③ 明确不生成属性代码的原因（低版本 SDK 无法编译）；
4. 终态：页面零改动，工程保持可编译（阻断≠报错，是 Skill 主动拦截）。
