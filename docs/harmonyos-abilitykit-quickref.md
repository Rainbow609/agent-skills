## AbilityKit 是什么（一句话）

应用程序开发和运行的**应用模型**：应用组件（UIAbility/ExtensionAbility）、生命周期调度、
组件间交互、进程线程管理、上下文环境——Stage 模型的地基。

## 四大使用场景（manbo 相关度）

| 场景 | 内容 | 相关度 |
| --- | --- | --- |
| 多 Module 开发 | HAP（功能）/ HAR + HSP（代码资源共享） | ⭐ manbo：entry HAP + reader-kit HAR 正是此模型 |
| 应用内交互 | UIAbility 间跳转（startAbility 等） | ⭐ 阅读器各页跳转 |
| 应用间交互 | 拉起其他应用（支付/分享类） | 中 |
| 跨设备流转 | 跨端迁移 + 多端协同 | ⭐ manbo 接续调研的框架底座（见记忆 continuation 三件套） |

## 能力范围清单（查 API 的目录）

进程创建销毁与生命周期调度｜组件运行入口与生命周期｜应用上下文与系统环境监听｜**启动框架**（冷启动优化）｜
**意图框架**（Insight Intent）｜应用流转｜多包机制/共享包/应用信息配置｜快捷方式｜访问控制｜
密码自动填充。亮点：UI 与业务逻辑分离、组件级跨端迁移、多设备多窗口（组件管理与窗口管理架构解耦，无屏可裁剪窗口）、
规范化后台进程治理（后台不能随意驻留）。

**与其他 Kit 关系**：UIAbility 里用 ArkUI（组件/事件/动效/状态管理）；ArkTS 提供语言运行时。

## 🌟 模拟器能力差异清单（测试前必读）

支持模拟器开发，但与真机有差异：

- ❌ 不支持拉起垂类应用面板；❌ 以免安装方式拉起元服务；❌ App Linking 应用间跳转；
  ❌ Deep Linking 应用选择框（匹配多个时无法弹选择）。
- ✅ **可安装未签名应用**，受限开放权限**自动放行**不做授权校验（真机校验签名与授权状态）——
  这是「模拟器免签直装」的官方口径。
- ❌ 不支持安装签名 Profile 类型为**发布**的应用。
- ⚠️ NDK 应用的 `.so` 与模拟器 CPU 架构不兼容时不支持安装（ABI 兼容表见官方）。
