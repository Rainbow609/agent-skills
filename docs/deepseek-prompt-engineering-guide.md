# DeepSeek 使用与提示工程：清华《从入门到精通》精炼

> 适用前提：需要选择「推理模型 vs 通用模型」、为复杂任务设计提示语链、或做中文内容生产（文案/营销/公众号/微博/小红书/抖音）时，用本文做速查。
> 来源：清华大学新闻与传播学院新媒体研究中心《DeepSeek：从入门到精通》（余梦珑博士后，@新媒沈阳团队），104 页 PDF。PDF 未标注出版日期，正文以 DeepSeek-R1、GPT-o3 为参照，推断成书于 2025 年初。
> 证据分级：**[原文]** 书中明确表述（属作者经验/观点，非受控实验）｜**[推导]** 本文据原文归纳｜**[存疑]** 原文给出数字但无方法说明。
> 复核时间 2026-10-23（全文逐页读取）。**模型能力相关结论有时效性**，提示工程方法部分基本与模型无关。

## 0. 先记住

1. **选模型看任务类型，不看热度**：数学/逻辑/代码/复杂拆解选推理模型；创意写作、多轮对话、开放问答选通用模型。推理模型不是全面更强，只在训练目标领域显著占优 `[原文]`。
2. **两类模型的提示策略相反**：推理模型「要什么直接说」，强行拆步骤反而限制它；通用模型「缺什么补什么」，需要显式步骤、示例和 CoT 引导 `[原文]`。
3. **复杂任务靠提示语链，不靠一条巨型提示**：分解 → 逐段生成 → 中间校验 → 综合，比一次性要求全部输出更稳 `[推导]`。
4. **质量瓶颈在人不在模型**：输入定义与迭代优化决定上限；生成后必须经过筛选与人工主观优化 `[原文]`。
5. **反对幻觉靠流程**：要求区分事实/推测、给出处、多源验证，而不是指望模型「不要编」 `[推导]`。

## 1. 两类模型：能力边界与提示差异

| 维度 | 推理模型（R1、o3 类） | 通用模型（GPT-4、BERT 类） |
| --- | --- | --- |
| 优势 | 数学推导、逻辑分析、代码生成、复杂问题拆解 | 文本生成、创意写作、多轮对话、开放问答 |
| 劣势 | 发散性任务（诗歌、头脑风暴） | 需要严格逻辑链的任务（数学证明） |
| 提示方式 | 简洁，只给目标和边界，信任其内化推理 | 结构化、补偿性引导：分步、示例、格式约束 |
| 常见误用 | 角色扮演/启发式提示干扰逻辑主线；过度拆步骤 | 直接抛复杂推理题，不验证结果 |

「快思慢想」的机制解释 `[原文]`：快速模型基于概率预测，响应快、成本低，擅长结构化明确问题；慢速模型基于链式思维逐步推理，成本高，擅长多维、非结构化问题。选型即是在「响应速度/成本」与「推理深度」之间取平衡。

## 2. 任务 → 模型 → 提示策略对照

| 任务 | 模型 | 提示重点 | 要避免 |
| --- | --- | --- | --- |
| 数学证明 | 推理 | 直接提问 | 冗余拆解（先画图、再列公式） |
| 数学证明 | 通用 | 显式分步 + 示例 | 直接提问（易跳步） |
| 创意写作 | 推理 | 给角色/风格，鼓励发散 | 过度约束逻辑与顺序 |
| 创意写作 | 通用 | 明确约束（主题、字数、元素） | 「自由创作」式开放指令 |
| 代码生成 | 推理 | 简洁需求 | 分步指导（先写递归函数……） |
| 代码生成 | 通用 | 细化步骤、输入输出格式、测试样例 | 模糊需求（「写个排序」） |
| 多轮对话 | 通用 | 自然交互 | 强制逻辑链条（「分三点回答」） |
| 多轮对话 | 推理 | 明确对话目标 | 情感化、开放发散提问 |
| 逻辑分析 | 推理 | 直接给复杂问题 | 主观引导（「你认为哪种对」） |
| 逻辑分析 | 通用 | 拆分问题、逐步追问 | 一次性抛复杂逻辑 |

## 3. 需求表达公式（比「写个好提示」更可操作）

| 需求类型 | 公式 | 适用 |
| --- | --- | --- |
| 决策 | 目标 + 选项 + 评估标准 | 方案取舍、风险评估、选型 |
| 分析 | 问题 + 数据/信息 + 分析方法 | 趋势、归因、模式发现 |
| 创造性 | 主题 + 风格/约束 + 创新方向 | 文案、命名、概念方案 |
| 验证 | 结论/方案 + 验证方法 + 风险点 | 事实核查、逻辑审查、可行性 |
| 执行 | 任务 + 步骤约束 + 输出格式 | 代码、计算、流程落地 |

示例（执行类）：「把这段 C 代码转成 Python，要求：① 保持时间复杂度；② 用 numpy 优化数组操作；③ 输出带计时测试的完整代码。」——目标、约束、交付物齐全，且把验收标准写进了提示 `[原文]`。

## 4. 提示语的结构与元素

- **三段结构**：指令（做什么）+ 上下文（背景、材料、约束）+ 期望（输出形式、质量标准）。
- **六种类型**：指令型、问答型、角色扮演型、创意型、分析型、多模态。
- **三类元素** `[原文]`：
  - 信息类：主题、背景、数据、知识域、参考材料；
  - 结构类：结构、格式、长度、风格；
  - 控制类：任务指令、约束条件、质量控制、输出验证、迭代指令。
- **组合矩阵的目标导向** `[推导]`：
  - 求准确：主题 + 数据 + 质量控制，辅以知识域 + 输出验证；
  - 求创意：主题 + 背景 + 约束，辅以参考 + 迭代；
  - 求效率：任务指令 + 结构 + 格式，辅以长度 + 风格；
  - 求一致：风格 + 知识域 + 约束，辅以格式 + 质量控制；
  - 求交互：迭代指令 + 输出验证 + 质量控制，辅以任务 + 背景。

## 5. 五条调优策略与五类陷阱

**策略** `[原文]`：

1. 精准定义任务：明确核心问题、具体化指令、删多余信息。
2. 适当分解复杂任务：分段生成、逐层深入、设置逻辑结构，降低认知负荷。
3. 引入引导性问题：多层次提问、要求对比/论证、引导多角度思考。
4. 控制提示长度：避免嵌套复杂指令，保持简洁，必要时分步给。
5. 灵活使用开放式/封闭式提示：开放题要探索空间，封闭题要明确限制与精准回答。

**陷阱与对策** `[原文]`：

| 陷阱 | 症状 | 对策 |
| --- | --- | --- |
| 缺乏迭代 | 追求一次完美；首轮不满意就放弃 | 增量法：基础提示起步，逐步加要求；让模型自评并给改进建议；准备后续追问 |
| 过度/模糊指令 | 提示冗长或过短；输出与预期严重不符 | 平衡详细度；突出最重要的 2–3 个要求；结构化组织；给输出示例 |
| 假设偏见 | 提示带立场；只得到支持性观点 | 中立措辞；显式要求多角度与反方论据；交叉验证 |
| 幻觉 | 数据无法验证；生造术语；对不确定事件过度具体 | 要求标注不确定性；区分已知事实与推测；多源验证；要求引用来源 |
| 忽视伦理 | 要求争议/非法内容；试图绕过安全机制 | 了解边界；合法合规；在提示中写入伦理约束；做影响评估 |

**幻觉五种表现** `[原文]`：数据误用（有数据但用错）、语境误解（理解错意图）、信息缺失（未能整合外部信息）、推理错误（逻辑漏洞/错误假设）、无中生有（完全虚构）。对应的提示策略是逐项预防：给准数据、说明意图、提供材料、要求分步推理、要求出处。

## 6. 提示语链：复杂任务的主力方法

提示语链 = 把复杂任务拆成可操作子任务的连续提示序列，本质是「元提示」：不只说做什么，还指导怎么做 `[原文]`。

**设计原则**：目标明确、逻辑连贯、渐进复杂、灵活适应、多样思考、反馈整合；结构尽量模块化以便复用。

**CIRS 模型**（每条链的四环节）`[原文]`：

- **C**ontext：背景与任务概述；
- **I**nstruction：具体指令；
- **R**efinement：对初稿修改完善；
- **S**ynthesis：整合所有输出形成最终成果。

**SPECTRA 任务分解** `[原文]`：Segmentation（切成 3–5 个独立但相关的部分）→ Prioritization（按重要性与逻辑排序）→ Elaboration（细化到 2–3 个行动项）→ Connection（说明子任务如何互相支撑）→ Temporal arrangement（排时序/依赖）→ Resource allocation（按复杂度分配注意力）→ Adaptation（每步评估后动态调整后续）。

**三种思维链框架** `[原文]`：

| 目标 | 框架 | 展开 |
| --- | --- | --- |
| 发散 | IDEA | Imagine 想象 → Diverge 发散 → Expand 扩展 → Alternate 替代 |
| 收敛 | FOCUS | Filter 筛选 → Optimize 优化 → Combine 组合 → Unify 统一 → Synthesize 综合 |
| 跨界 | BRIDGE | Blend 混合 → Reframe 重构 → Interconnect 互联 → Decontextualize 去情境化 → Generalize 泛化 → Extrapolate 推演 |

**三链融合** `[原文]`：逻辑链（论证严密）+ 知识链（领域知识激活）+ 创意链（独特见解）。动态优化靠四件事：平衡评估（三条链贡献度）、适应性切换（按任务阶段换侧重点）、交叉强化（用强链补弱链）、整合检查点（定期评估逻辑性/知识深度/创新度）。

## 7. 十二种高阶机制速查

不必每次全用；按任务缺口挑一个，作为提示语的「结构骨架」`[推导]`。

| 机制 | 解决的问题 | 一句话做法 |
| --- | --- | --- |
| PIA 语用意图分析 | 输出跑偏、重点不明 | 给意图分类（陈述/指令/表达/承诺/宣告）并标 1–10 强度，按强度分配篇幅 |
| TFM 主题聚焦 | 内容发散、离题 | 定义主题原型 → 建语义框架 → 排重点梯度 → 设主题引导词 |
| DES 细节增强 | 内容空泛 | 为每个概念建「数据/案例/感官/对比/时空」细节矩阵，做微观—宏观桥接 |
| CMM 跨域映射 | 缺少新视角 | 选源域 → 找映射点 → 生成类比 → 检查恰当性与局限 |
| CGS 概念嫁接 | 需要融合创新 | 两个输入概念 → 找共同特征 → 设融合点 → 构建涌现结构 |
| KTT 知识转移 | 把成熟领域做法搬到新领域 | 定义问题 → 找源域 → 抽象知识 → 分析结构相似性 → 映射并验证 |
| RCM 随机组合 | 思维卡住 | 建多元素库 → 随机抽取 → 强制联系 → 整合成概念 |
| EHS 极端假设 | 突破常规假设 | 列出领域常规假设 → 推向极端/反转 → 推演后果 → 提取创新点 |
| MCS 多重约束 | 需要创造性妥协 | 设多个冲突约束 → 分析冲突 → 在约束内找方案 → 必要时重构约束 |
| RSM 语体模拟 | 风格不像 | 定目标语体 → 收语料 → 分析词汇/句法/修辞/韵律 → 建语体指南 |
| EIS 情感融入 | 文字无感染力 | 定情感基调 → 建情感词库 → 设计情感曲线 → 在触发点植入场景细节 |
| RTA 修辞应用 | 表达平淡 | 选 2–3 种核心修辞 → 给示例 → 规划分布 → 防止过度 |
| 元叙事 | 需要自反/多层文本 | 嵌入式自反、递归元叙事、多重人格、读者互动四种框架 |

## 8. 内容生产场景：可复用的骨架

### 8.1 商业文案

三要素缺一不可 `[原文]`：**信息传递**（清晰、准确、相关）、**情感共鸣**（触动、共感、记忆）、**行动引导**（说服、激励、转化）。

- 信息传递：先定信息层级，再给每层字数/关键词限制，明确逻辑关系与受众特征，最后设计记忆点。
- 情感共鸣：指定情感基调 → 多感官场景 → 「问题—情感—解决方案」结构 → 价值主张 → 情感高潮 → 第二人称结语。
- 行动引导：行动词标题 → 明确具体动作 → 量化利益点 → 紧迫感（截止时间/限量）→ 社会证明 → 低门槛第一步 → 行动召唤 → 遗憾预防。

### 8.2 营销策划

三块交付物 `[原文]`：**创意概念**（跨领域联想、品牌 DNA、记忆点、情感地图、趋势挂钩）、**传播策略**（SMART 目标、2–3 类受众画像、7+ 渠道矩阵、分渠道内容、KOL 分层、时间线、KPI、危机预案）、**执行方案**（里程碑、15–20 个行动步骤，每步含责任人/起止时间/资源/完成指标、预算、质量控制点、风险矩阵、利益相关者沟通、应急预案、复盘机制）。

### 8.3 品牌故事

- **定位**：目标受众画像 + 3 个竞对差异 + 5 个品牌个性词 + 情感连接点 + 一句定位声明；避免过宽、模仿、僵化、能力不匹配。
- **价值主张**：3–5 个核心优势 + 痛点对应 + 情感价值 + 2–3 个证明点 + 差异化 + 简化版；避免复杂、只讲功能、夸大、同质化。
- **未来愿景**：5–10 年一句话愿景 + 行业影响 + 社会贡献 + 客户/员工价值 + 2–3 个创新项目 + 3–5 个里程碑 + 激励口号；避免抽象、只谈商业、与现状脱节。

### 8.4 年终总结

- 业绩回顾：成果概述 + 数据支撑 + 关键项目与个人角色；
- 成就展示：团队贡献 + 创新突破 + 个人荣誉；
- 未来规划：可度量目标 + 行动步骤与时间节点 + 个人成长方向。

### 8.5 平台差异（同一内容不能一套提示打天下）

| 平台 | 核心约束 | 提示设计重点 |
| --- | --- | --- |
| 公众号 | 私域、深读、平台规范、互动 | 标题给信息密度/差异价值/时效/调性；正文开篇 800 字抓问题，主体 2500 字放 3–4 个论点（观点+原理+2 案例+数据+专家），结尾 700 字总结/趋势/行动；论证要有证据链、递进、多视角 |
| 微博 | 实时、社交、话题引导、多媒体 | 短平快但价值密度高；分热点跟进/原创/话题引导/品牌营销/互动娱乐五类；主话题前置、相关话题 2–3 个、品牌话题收尾；发布节奏与评论/转发/私信互动一起设计 |
| 小红书 | 种草、社区、垂直专业；推荐流看首图标题，搜索看关键词 | 标题 15–25 字，含钩子+关键词+数字/方法+价值承诺；图片按封面/细节/场景/对比组织；正文按「钩子→个人经验→使用方法→效果→购买建议」；信任建设要展示背景、使用历程、真实体验、对比测评，并敢讲缺点 |
| 抖音 | 视觉冲击、短时吸引、强互动 | 开头 3 秒必须抓人；剧情紧凑、开篇冲突、结尾反转；情绪饱满；结尾设计互动/挑战；实用类要步骤清晰、语言简洁 |

## 9. 人机协作：三层概率与四种能力

**三层概率** `[原文]`：初始生成（AI 概率预测出初稿）→ 交互筛选（人通过对话/选择挑出较优）→ 主观优化（人基于自身能力做个性化改造）。三者是动态循环，不是一次性流水线。

**四种核心能力** `[原文]`：

| 能力 | 内涵 | 子项 |
| --- | --- | --- |
| AI 思维 | 理解 AI 决策逻辑与能力边界 | 算法思维、数据洞察、边界认知、协同意识 |
| 整合力 | 融合人机优势 | 跨域翻译、创意重组、资源编排、知识融合 |
| 引导力 | 主导交互过程 | 提示工程、对话管理、任务分解、质量控制 |
| 判断力 | 做输出的把关者 | 真伪辨识、价值评估、风险预测、情境适配 |

**使用层次** `[原文]`：基础层（单一任务、简单提示、被动应用）→ 进阶层（任务组合、结构化提示、主动优化）→ 创新层（流程再造、提示词艺术、创造性应用）。突破路径：建提示词体系 → 设计协作流程 → 发展创新方法 → 打造个人特色。

**质量归因** `[原文，存疑]`：输入质量 70% 取决于人，机器基础能力 80%，迭代优化 90% 取决于人；综合判断人的主导作用约 65%。书中未给实验方法与样本，数字只宜作方向性参考，不宜当精确结论。

## 10. 知识唤醒：把隐性经验变成可用提示

书中把知识分为两层 `[原文]`：

- **人的具身知识**：直接经验、现场感知、身体化技能、情境记忆、实践智慧；
- **AI 的形式知识**：文本信息、逻辑规则、统计规律、关联模式、抽象概念。

桥接机制是「唤醒」：AI 提问触发场景回溯 → 人把经验描述成清晰表达 → 结构化后与概念连接 → AI 补充形式知识、识别模式 → 输出融合具身性的内容。

三条唤醒路径 `[原文]`：

- **情感唤醒**：用惊异感、好奇心、探索欲打破固有思维；AI 负责发现盲点、提供反常视角、制造碰撞。
- **经验唤醒**：场景还原、多维模拟、经验链接；把默会知识通过实践回溯和技能映射显性化。
- **关联唤醒**：跨域联系、类比推理、整体观照；把新旧知识融合、跨学科整合、做突破性联想。

## 11. 落地建议（对我们的用法）

1. **默认按任务选模型**：代码/数学/复杂拆解用推理模型，提示只给目标、约束和验收标准；创意/对话/开放问答用通用模型，给结构、示例和分步要求。
2. **超过「一次输出装不下」的任务就上链**：先用 SPECTRA 拆，逐段用 CIRS 生成与 refine，最后 synthesis；不要把所有要求塞进一条提示。
3. **把验收标准写进提示**：字数、格式、必须包含的元素、禁止项、失败示例，比「写好一点」有效。
4. **内容生产先定平台再写提示**：平台的分发机制决定标题、结构、图片/视频节奏；同一主题在四个平台应是四套提示。
5. **抗幻觉做成固定动作**：要求「区分事实与推测 + 给出处 + 对不确定处标注」，关键结论再交叉验证。
6. **迭代是流程不是补救**：生成 → 筛选 → 人工优化 → 回灌约束；把每次有效的提示沉淀成模板库。
