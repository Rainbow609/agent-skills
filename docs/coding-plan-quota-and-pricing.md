# 订阅制 Coding Plan 额度与单价速查（OpenCode Go / Z.ai GLM / Kimi 会员）

> 适用前提：回答「该不该换订阅、换哪张更划算」这类决策时，需要一套可比口径的数据底稿——
> 各族订阅的额度单位不统一（美元额度 / 积分 / prompt 数 / token 池），直接对比会得出反向结论。
> 本文所有数字均抓取自厂商页面（2026-10-15），第三方反推的数字单独标注置信度。
> 汇率口径：**1 USD ≈ 7.1 CNY**（近似，仅用于跨币种比较）。厂商随时调价，引用前请复核「来源」。

## 核心结论

1. **OpenCode Go / Go Plus 的额度单位是「美元额度」，不是请求数。** 每个模型有独立的月度美元上限，
   互相**不可挪用**（$180 的 K2.7 Code 额度花不到 K3 上）；5 小时窗口只有月额度的 20%、周窗口 50%，
   突发流量真正的瓶颈是 5 小时窗口而不是月额度。Go $10 各模型额度与月费之比最高到 6×（Kimi K2.6 $240/$40）。
2. **缓存命中价决定 agent 账单。** coding agent 流量九成以上是缓存输入：GLM-5.3-Flash 缓存命中 $0.03/1M，
   DeepSeek V4.1 Flash 只有 $0.003/1M（便宜 10 倍），所以按真实流量画像，DeepSeek 平峰比 GLM 便宜约 4 倍；
   但 DeepSeek 高峰全项翻倍，GLM 无峰谷加价，统一画像下两者平峰几乎同价（$0.136 vs $0.130 每 1M 输入+0.2M 输出）。
3. **Z.ai 订阅的积分系数对旗舰更友好。** Lite 跑 GLM-5.3-Flash 的等效 API 价值只有月费的 1.3–2.6 倍，
   跑 GLM-5.3 却有 3.8–7.5 倍——同一张卡，用旗舰的每美元产出是 Flash 的 **2.9 倍**（Flash 每 1M 输入+缓存+输出
   消耗的积分是 5.3 的约 2.9 倍，而 API 标价只低约 9 倍）。官方「最多省 92%」的说法只对 GLM-5.3 成立。
4. **Kimi 在 2026-09 改了档位体系，老套餐反而更划算。** 老档位（Adagio/Andante/Moderato/Allegretto/Allegro）
   保留「每周独立额度 + 5 小时滚动窗口 + Kimi Code 20× 系数」；新档位（Go/Plus/Pro/Max）取消周窗口、
   改为月池，并取消了 Kimi Code 的专属系数。第三方实测：老 Allegretto ¥39.8/千万 tokens → 新 Pro ¥76.5/千万（+92%）。
   老套餐可续订且规则不变，**不要为了「升级」而迁移**。
5. **换订阅的判断取决于主力模型，不存在单一最优解。** 主力是「跑量模型」（GLM-5.3-Flash、DeepSeek）→ Go Plus 明确更优；
   主力是 Kimi K3 → Go Plus 未必更多，且会失去 1M 上下文、高速版与 Kimi 会员本体权益。

## 七、口径陷阱清单

- **「额度」不是请求数**：Go/Go Plus 的分模型月额度是**美元额度**，按模型 token 单价扣减；
  Z.ai 是**积分**；Kimi 是**共享 token 池**。换算成请求数必须附带画像假设（见 §1）。
- **缓存的权重被严重低估**：两家官方预估请求数都建立在 5–9 万缓存 token/请求之上；
  若你的缓存命中率低（频繁换仓库、上下文频繁失效），实际可跑请求数会显著低于表格值。
- **峰谷时段定义不同**：DeepSeek 高峰按 UTC 周一至周五两个窗口（UTC+8 09:00–12:00、14:00–18:00）；
  Z.ai 订阅高峰按新加坡时间周一至周五 14:00–18:00；两者重叠的那 4 小时是双重高峰。
- **订阅的「倍率」是上限**：等效价值倍数需要「全部落在平峰 + 每次都塞满缓存」才拿到上缘；
  Z.ai 因平峰时段占 88% 的钟点，现实中偏向上缘，但仍不等于保底。
- **老套餐 ≠ 新套餐**：Z.ai 与 Kimi 都发生过代际切换，老用户保留原规则。
  判断「该不该升级」时必须区分自己处于哪一代，别把官方新档位页面的数字当成自己的现状。
- **置信度分层**：§2（API 单价）、§3（Go 额度与预估请求）、§4（Z.ai 价格与积分规则）、
  §5 的价格与规则差异均由官方页面直出；**§5 的额度 token 数字为第三方实测反推**，只作量级参考。
